# หมวดหมู่และวิธีนับ

ใช้หลายมิติควบคู่กัน เพื่อให้ผู้ใช้เลือกนิยามได้โดยไม่เปลี่ยนข้อมูลต้นทาง

| มิติ | ค่า |
|---|---|
| Platform | ค่าที่รองรับใน `registry.store.PLATFORMS`; ทุกแพลตฟอร์มใช้เกณฑ์ scope เดียวกัน |
| Thai relation | thai_language, self_declared_thai, thai_community, thai_agency, multiple, unknown |
| Presentation | png, live2d, 3d, mixed, unknown |
| Roles | streamer, singer, artist, rigger, entertainer, educator, other; เลือกหลายบทบาทได้ |
| Review | needs_evidence, verified, rejected |
| Event date precision | day, month, year, unknown |

`self_declared_thai` ใช้การประกาศสาธารณะของเจ้าตัว ส่วนภาษา ประเทศที่ตั้งบัญชี และค่ายเป็นหลักฐานคนละประเภท

## เกณฑ์ยืนยันไม่ขึ้นกับแพลตฟอร์ม

VTuber / VStreamer ที่ไลฟ์เฉพาะ Twitch หรือ TikTok สามารถผ่าน review ได้
**ไม่จำเป็นต้องมี YouTube หรือมีมากกว่าหนึ่งแพลตฟอร์ม** และการมี YouTube
หรือหลายบัญชีก็ไม่ได้ทำให้ผ่านโดยอัตโนมัติ จำนวนผู้ติดตามไม่ใช่เงื่อนไขนี้เช่นกัน

แยกข้อเท็จจริงสามเรื่อง: บัญชีที่ resolve แล้ว, persona ที่ผ่านการตรวจ virtual
presentation/ความเกี่ยวข้องกับไทย, และหลักฐานว่า persona ใช้บัญชีนั้นจริง
หน้าโปรไฟล์สาธารณะที่เจ้าตัวเขียนเองสามารถเป็นหลักฐานของทั้ง persona และ
บัญชีเดียวกันได้ ไม่ต้องมี cross-link ไปอีกเว็บไซต์เพื่อให้มีสิทธิ์ผ่าน review

รูปอนิเมะ ชื่อเหมือนกัน หรือแท็กอย่างเดียวไม่ทำให้ระบบยืนยันอัตโนมัติ ผู้ตรวจ
ยังต้องบันทึกหลักฐาน/บทบาท/Thai relation/ownership พร้อมผู้ตรวจและวันตรวจ
หลักฐานไม่พอให้ `needs_evidence` ไม่ใช่ `rejected` เพราะไม่มี YouTube

## สถานะกิจกรรม

ค่าเริ่มต้นวัดกิจกรรมย้อนหลัง 90 วัน รวมวันอ้างอิง สามารถปรับ `--active-days` และต้องแสดงค่าด้วยทุกครั้ง

| สถานะที่รายงาน | หลักเกณฑ์ |
|---|---|
| active_streaming | พบหลักฐาน live ที่ผ่าน review ในหน้าต่างเวลา |
| active_posting | พบ post/video แต่ไม่มีหลักฐาน live ในหน้าต่างเวลา |
| pre_debut | มีประกาศ debut ระบุวันที่ในอนาคตและยังไม่มีกิจกรรมที่ใช้ยืนยัน |
| hiatus | ประกาศพักล่าสุด ยังไม่มีเหตุการณ์ return/redebut ที่ตามมา |
| graduated | ประกาศจบกิจกรรมล่าสุด ยังไม่มี return/redebut ที่ตามมา |
| no_recent_evidence | เคยมีหลักฐานกิจกรรม แต่ไม่มีรายการในหน้าต่างเวลา |
| unknown | หลักฐานไม่เพียงพอ |
| conflict_needs_review | สถานะที่ยืนยันขัดกัน หรือพบกิจกรรมหลัง hiatus/graduation ที่ยังไม่ตรวจการกลับมา |

`graduated` และ `hiatus` มาจากประกาศของเจ้าตัว/ค่าย การหายไป 180 วัน การปิดช่อง หรือ API หาไม่เจอเพียงอย่างเดียวให้ใช้ unknown/no_recent_evidence การโพสต์คลิป archive หลัง graduation ไม่ได้ลบประวัติการแกรด

## เหตุการณ์

| Event | ความหมาย |
|---|---|
| debut | เริ่ม persona ตามประกาศ |
| redebut | เปิดตัว persona เดิมใหม่ตามคำประกาศ |
| rebrand | เปลี่ยนชื่อหรือทิศทางของ persona |
| model_reveal | เปิดตัวโมเดล; ไม่ถือเป็น redebut โดยอัตโนมัติ |
| hiatus | ประกาศพัก |
| graduation | ประกาศยุติบทบาท |
| return | ประกาศกลับมา |
| channel_migration | ประกาศย้ายบัญชี/แพลตฟอร์ม |

"ชุบตัว" บันทึกเป็น `publicly_disclosed_continuity` เมื่อมีความเชื่อมโยงที่เจ้าตัวหรือค่ายเปิดเผยอย่างชัดเจน ไม่บันทึกการเดาจากเสียง เพื่อน หรือข่าวลือ และไม่นับความเชื่อมโยงนี้เป็น "จำนวนคนจริง"

วันที่รู้เพียงเดือน/ปีเก็บตามความละเอียดนั้น เหตุการณ์ดังกล่าวยังไม่ใช้ตัดสินสถานะรายวัน รายงานแสดงจำนวนเหตุการณ์ที่ขาดวันแน่นอนแยกไว้

## หน่วยของตัวเลข

- จำนวนบัญชี: unique platform ID พร้อม namespace
- จำนวน persona: เฉพาะ persona ที่ผ่าน review; หนึ่ง persona มีหลายบัญชีได้
- จำนวนเหตุการณ์: persona เดิม redebut หลายครั้งนับหลายเหตุการณ์
- จำนวน persona ที่เคย redebut: ตัดซ้ำตาม persona ID ก่อนนับ
- บัญชีที่อ้างอิงแต่ละแหล่ง: หนึ่งบัญชีอยู่หลายแหล่งได้ ยอดรวมจึงบวกตรง ๆ ไม่ได้
- ค่า 0 ในชุดที่ยังไม่มีการตรวจ: ยังไม่มีหลักฐานยืนยันในทะเบียน
