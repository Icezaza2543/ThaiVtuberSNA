## 1. ข้อมูลใดเกี่ยวข้อง

| กลุ่ม | ข้อมูลและการใช้ |
| --- | --- |
| ครีเอเตอร์/วิดีโอ | รหัสและชื่อช่อง สังกัดที่บันทึก ข้อมูลรายการวิดีโอ ช่วงเวลา และข้อมูลสาธารณะที่เกี่ยวข้อง เพื่อจัดทะเบียนและอธิบายผลรวม |
| ผู้มีปฏิสัมพันธ์ | รหัสบัญชี ชื่อ/URL ที่มีในแหล่งหลักฐาน รหัสนามแฝง และประวัติการปรากฏที่ระดับช่อง/วิดีโอ/เวลา ตามข้อมูลที่เก็บได้ ใช้เชื่อมหลักฐานและวิเคราะห์ผลรวมในพื้นที่จำกัดสิทธิ์ |
| ผู้เปิดหน้าเว็บ | หน้าเว็บโหลดไฟล์สถิติและฟอนต์; ผู้ให้บริการ hosting หรือเครือข่ายอาจได้รับ IP, user agent และข้อมูลคำขอ ผู้ดำเนิน deployment ต้องเปิดเผย log/cookie ที่เพิ่มจริง |
| ผู้ส่งคำร้อง | อีเมล รายละเอียดปัญหา และหลักฐานที่จำเป็นต่อการตรวจสิทธิ ใช้ตอบและดำเนินคำร้องอย่างจำกัดวัตถุประสงค์ |

ข้อมูลที่เปิดสาธารณะอาจยังเป็นข้อมูลส่วนบุคคล รวมถึงข้อมูลของครีเอเตอร์เมื่อระบุบุคคลได้โดยตรงหรือโดยอ้อม รหัส HMAC เป็นนามแฝงที่ยังเชื่อมข้อมูลได้ ไม่ใช่หลักฐานว่าข้อมูลนิรนาม หลักการนี้สัมพันธ์กับนิยามข้อมูลส่วนบุคคลตามมาตรา 6 ของ [พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล](https://ictc.ops.moc.go.th/th/content/category/detail/id/142/iid/9152)

แหล่งข้อมูลรวมถึงข้อมูลสาธารณะบน YouTube และทะเบียน/หลักฐานที่โครงการอ้างอิง การเก็บจากแหล่งอื่นที่ไม่ใช่เจ้าของข้อมูลโดยตรงต้องประเมินหน้าที่แจ้งและข้อยกเว้นที่ใช้ได้ ไม่ถือว่าการโพสต์สาธารณะเป็นความยินยอมให้โครงการทำทุกกิจกรรม

## 2. วัตถุประสงค์และฐานกฎหมาย

วัตถุประสงค์คือศึกษาความสัมพันธ์เชิงโครงสร้าง ตรวจคุณภาพและความต่อเนื่องของหลักฐาน จัดทำผลรวม และจัดการความถูกต้อง/คำร้อง ไม่ใช่การโฆษณาตรง การระบุตัวจริง หรือการอนุมานข้อมูลอ่อนไหว

**ยังไม่มีหลักฐานการประเมินฐานกฎหมายรายกิจกรรมครบในเอกสารที่ตรวจครั้งนี้** จึงไม่ประกาศว่าโครงการใช้ฐานวิจัย ประโยชน์โดยชอบด้วยกฎหมาย หรือความยินยอมสำเร็จแล้ว ผู้ควบคุมข้อมูลต้องบันทึกความจำเป็น ความได้สัดส่วน มาตรการคุ้มครอง และผลกระทบต่อบุคคลตามฐานที่ใช้จริงก่อนเก็บเพิ่มหรือเปลี่ยนวัตถุประสงค์ หากอาศัยความยินยอมต้องมีวิธีถอนที่ใช้ได้จริง

## 3. ขอบเขตการจัดเก็บและเปิดเผย

สถาปัตยกรรมปัจจุบันกำหนดให้ข้อมูลผู้มีปฏิสัมพันธ์รายบุคคลอยู่ในสมุดงานเดิมที่จำกัดสิทธิ์ ประมวลผลวิเคราะห์ในหน่วยความจำ แล้วเผยแพร่เฉพาะข้อมูลครีเอเตอร์และผลรวม กุญแจและ credentials แยกออกจาก Git และสมุดงาน ไม่จงใจเก็บข้อความความคิดเห็นหรือแชตดิบผ่านเส้นทางที่รองรับ

หน้าเว็บสาธารณะไม่มีช่องให้ค้นตัวผู้มีปฏิสัมพันธ์ ไม่ให้สิทธิเปิดสมุดงานส่วนตัว และ regression ตรวจว่าชุดไฟล์ `web/` ไม่มีข้อมูล identity ที่ห้ามเผยแพร่ **ขอบเขตนี้ไม่ใช่การรับรองว่า Git history, fork, cache หรือไฟล์เก่าทุกชุดไม่มีข้อมูลส่วนบุคคล** การแก้ประวัติหรือเรียกคืนสำเนาต้องแยกประเมิน

ผู้เข้าถึงข้อมูลส่วนตัวต้องเป็นผู้ที่ได้รับอนุญาตตามหน้าที่ การซ่อน tab ไม่ใช่การจำกัดสิทธิ์อ่าน และการได้รับสิทธิ์ในสมุดงานอาจทำให้เห็นข้อมูลส่วนตัวหลายประเภท ผู้ดูแลต้องทบทวนสิทธิ์จริงเป็นระยะ

- เมื่อดู repository ผ่าน GitHub หรือ deployment ภายนอก ผู้ให้บริการนั้นจัดการข้อมูลการเข้าถึงภายใต้นโยบายของตน
- การคลิกลิงก์ไป YouTube หรือเว็บไซต์ต้นทางอยู่ภายใต้นโยบายของเว็บไซต์นั้น

ซอร์ส frontend ที่ตรวจในรอบนี้ไม่มีระบบเข้าสู่ระบบสำหรับผู้ชมเว็บหรือโค้ด analytics/cookie ที่โครงการเพิ่มเอง ข้อความนี้ไม่ครอบคลุมสคริปต์ที่ deployment อื่นอาจเพิ่ม และไม่เท่ากับบอกว่าไม่มีการรับข้อมูลเครือข่ายจากบุคคลที่สาม

## 5. ระยะเวลาเก็บและการลบ

**ยังต้องกำหนดตารางระยะเวลาเก็บที่ใช้งานจริง** แยกข้อมูลระบุตัว/นามแฝง เหตุการณ์ ข้อมูลครีเอเตอร์ ผลรวม log คำร้อง และสำรองข้อมูล โดยผูกกับวัตถุประสงค์ ฐานกฎหมาย และเงื่อนไขแหล่งข้อมูล ไม่เก็บโดยไม่มีกำหนดเพียงเพราะเป็นงานวิจัย

หากข้อมูลได้มาจาก YouTube API ต้องพิจารณากฎ refresh/delete แยกตามประเภท การมีข้อยกเว้นสำหรับสถิติหรือ derived metrics ไม่ขยายไปยังข้อมูลส่วนบุคคลทุกชนิด อ่าน [YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies) และ [เงื่อนไข derived metrics](https://developers.google.com/youtube/terms/derived-metrics-policy)

ไม่มีการอ้างว่าโค้ดปัจจุบันลบอัตโนมัติภายในระยะเวลาที่กฎหมายหรือแพลตฟอร์มกำหนด หากมีคำร้องลบ ต้องประเมินข้อมูลต้นทาง ผลรวมที่ต้องสร้างใหม่ archive สำรอง และการป้องกันนำเข้าซ้ำร่วมกัน พร้อมบันทึกข้อยกเว้นการเก็บที่จำเป็นอย่างจำกัดสิทธิ์

เมื่อพบการเปิดเผยหรือเข้าถึงโดยไม่ได้รับอนุญาต ผู้ดูแลต้องจำกัดเหตุ เก็บหลักฐานเท่าที่จำเป็น ประเมินความเสี่ยง และดำเนินการแจ้งที่กฎหมายกำหนดตามข้อเท็จจริง ไม่อ้างว่าการมี regression เพียงพอจะป้องกันทุกเหตุ แจ้งช่องโหว่ตาม [SECURITY.md](../../SECURITY.md)

การเปลี่ยนวัตถุประสงค์หรือประเภทข้อมูลต้องทบทวนฐานกฎหมายและประกาศให้ตรงกับการปฏิบัติจริงก่อนดำเนินการ การลงวันที่ใหม่ไม่ใช่ความยินยอมย้อนหลัง
